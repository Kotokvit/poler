# Формат `.poler` v1 — спецификация

Источник истины: `crates/poler-archive/src/stream_writer.rs` (константы и
раскладка), байт-в-байт совпадает с poler-engine v0.61.0.

## Раскладка файла

```text
[0..8)                  magic "POLERARC"
[8..)                   физические чанки подряд:
                          blake3[32] raw_len u32 stored_len u32
                          method u8 pad[3]  payload[stored_len]
...                     логический индекс (24 Б/чанк):
                          raw_off u64 stored_off u64 raw_len u32 pad u32
...                     файловая таблица:
                          name_len u16 name[..] raw_off u64
                          raw_len u64 sha256[32]
[len-104..len)          трейлер "POLEREND" + геометрия
```

Все числа — **little-endian**.

## Константы

| Имя | Значение |
|---|---|
| `MAGIC_START` | `POLERARC` (8 байт) |
| `MAGIC_END` | `POLEREND` (8 байт, начало трейлера) |
| `POLER_VERSION` | 1 |
| `TRAILER_SIZE` | 104 байта |
| `CHUNK_HEADER_SIZE` | 44 байта (blake3 32 + raw_len 4 + stored_len 4 + method 1 + pad 3) |
| `INDEX_ENTRY_SIZE` | 24 байта |

## Методы сжатия чанков

| method | значение | |
|---|---|---|
| 0 | STORE | без сжатия (несжимаемые данные) |
| 1 | ZFAST | zstd уровень ~3 |
| 2 | ZDEEP | zstd уровень ~15 |

Ярус выбирается автоматически (`CompressTier::Auto`): чанк сжимается
zstd-3; если выигрыш лучше 2:1 — пробуется zstd-15, берётся меньший результат.

## Чанкинг и дедуп

- **FastCDC** (нормализованный): границы чанков зависят только от
  содержимого (gear-хеш), 64 КиБ … 1 МиБ, цель 256 КиБ. Одинаковые данные
  режутся одинаково при любой позиции в потоке.
- **Дедуп**: BLAKE3-хэш чанка → u64-префикс в RAM-реестре (~24 Б/чанк);
  при совпадении префикса полная 32-байтная проверка чтением заголовка
  уже записанного чанка. Коллизия префикса (~2⁻⁶⁴ на пару) стоит лишь
  потери дедуп-возможности, целостности не касается.
- Логический индекс хранит все вхождения, физические чанки — уникальные.

## Файловая таблица

Поток tar распознаётся на лету (TarObserver: ustar + GNU longname 'L'/'K' +
base-256 размеры) — имена/смещения/SHA-256 каждой записи уходят в таблицу.
Поток без tar-магии = одна запись (name_hint).

**Пустые каталоги не сохраняются** (таблица содержит только файлы) —
уровень v0.61.0 движка, поведение сохранено для байт-совместимости.

## Целостность

- SHA-256 **всего потока** — в трейлере (`stream_sha256_hex`);
- SHA-256 **каждой записи** — в таблице;
- `verify()` прогоняет обе цепочки (в O(log n) через mmap-индекс);
- распаковка сверяет SHA-256 каждого файла на месте (`extract_all`).

## Crash-safety

Запись идёт в `<out>.poler.part`, атомарный rename в конце; брошенный
без `finish()` писатель удаляет temporaries. Sidecar `.part.files` —
только метаданные (имена/смещения/SHA-256), никогда сырые данные.

## RAM-дисциплина

Буфер нарезки ≤ max+64 КиБ (~1.1 МБ), реестр дедупа ~24 Б/чанк,
логический индекс 24 Б/чанк, zstd-контексты создаются один раз.
Пик RSS сообщается в статистике (`VmHWM`).

## Восстановление после повреждений

Точечная порча: SHA-256 записи не сходится → `files_bad`, остальные записи
извлекаются. Порча трейлера/индекса: `open()` отклоняет архив целиком
(«полный» формат не гарантирует сканирование хвост-вперёд — см. roadmap
v2: dual-магия в начале каждого чанка).
